# 김종록 잡코리아 이력서 입력용 문안

## 이력서 제목

Spring Boot 백엔드와 RAG·LLM 기능을 서비스로 연결하는 개발자 김종록입니다

## 희망 직무

- 1순위: 백엔드 개발자
- 2순위: AI 응용 서비스 개발자
- 3순위: Java·Python 기반 풀스택 개발자

## 간단 소개

병원 전산 운영 3년 11개월 동안 여러 진료·행정부서의 장애에 대응하고 사용자 요청을 처리하며, 문제를 단순 증상이 아닌 업무 흐름과 시스템 구조의 관점에서 파악하는 경험을 쌓았습니다.

이후 Spring Boot 기반 Backend와 React 화면을 구현하고, 머신러닝·딥러닝 모델 개발과 LLM 에이전트·RAG 챗봇 구현을 경험했습니다. 5인 팀의 Project Leader로 참여한 BidMatch에서는 인증·기업정보·고객센터·알림 API와 AI 기능을 연결하고, AI 결과를 Backend 규칙과 응답 검증·대체 처리로 보완해 AI 자동화 테스트 242건을 통과했습니다.

운영 환경에 대한 이해를 바탕으로 AI 기능을 안정적인 Backend 서비스에 연결하고, 예외 상황에서도 사용자가 신뢰할 수 있는 결과를 제공하는 개발자로 성장하고 있습니다.

## 자기소개서 1. 지원동기와 입사 후 포부

병원 전산실에서 여러 진료·행정부서의 요청과 장애를 처리하며, 사용자가 안정적으로 업무를 이어가게 만드는 시스템의 가치를 배웠습니다. 문제를 해결하는 과정에서 단순한 장비 지원을 넘어 서비스가 어떤 구조로 동작하는지 직접 만들고 싶다는 목표가 생겼고, Java·Spring Boot 기반 풀스택 과정을 통해 개발자로 전환했습니다.

이후 정형 데이터 머신러닝, 영상·시계열 딥러닝, LLM 에이전트를 차례로 구현하고 최종적으로 BidMatch에서 Spring Boot 백엔드와 FastAPI AI 기능을 하나의 서비스 흐름으로 연결했습니다. 특히 LLM의 답을 그대로 사용하지 않고 원문 근거와 Backend 규칙으로 재검증하고, 실패 시에도 기본 기능을 유지하도록 설계하면서 실제 서비스에서는 정확성뿐 아니라 예외 처리와 운영 안정성이 중요하다는 것을 배웠습니다.

입사 후에는 먼저 기존 서비스의 도메인과 운영 흐름을 빠르게 파악하고, 테스트와 기록을 바탕으로 신뢰할 수 있는 백엔드 기능을 만들겠습니다. 이후에는 AI가 필요한 지점과 규칙 기반 처리가 더 적합한 지점을 구분해, 사용자에게 실제 가치를 주는 AI 응용 서비스를 구현하는 개발자로 성장하겠습니다.

## 자기소개서 2. 강점과 성장 과정

저의 강점은 문제가 생겼을 때 현상만 고치는 데서 멈추지 않고, 재발할 수 있는 구조를 찾아 정리하는 점입니다. 병원 전산 운영 중에는 다양한 부서의 요청을 우선순위와 영향 범위에 따라 분류하고, 반복 문의는 매뉴얼과 교육 자료로 남겼습니다. 이 경험은 개발 과정에서도 이어졌습니다.

BidMatch에서는 여러 팀원이 동시에 DB 스키마를 변경하면서 Flyway 버전과 체크섬 충돌이 발생했습니다. 이미 적용된 마이그레이션을 임의로 수정하면 다른 개발자의 DB와 배포 환경이 더 불안정해질 수 있다고 판단했습니다. 기존 적용 이력을 보존한 채 새 버전의 후속 마이그레이션을 추가하고, 레거시 컬럼 차이를 보정해 빈 DB와 기존 DB 모두에서 애플리케이션이 실행되도록 정리했습니다.

이 경험을 통해 문제 해결은 빠르게 코드를 바꾸는 것보다 변경의 영향 범위를 확인하고 팀이 다시 같은 문제를 겪지 않도록 기준을 남기는 일까지 포함한다는 것을 배웠습니다. 앞으로도 원인을 설명할 수 있고 동료가 이어받기 쉬운 코드를 만드는 개발자가 되겠습니다.

## 자기소개서 3. 직무 관련 전문 경험

5인 팀의 Project Leader로 참여한 BidMatch에서 기업회원이 가입한 뒤 기업정보와 면허·실적을 관리하고 공고를 검토하는 핵심 사용자 흐름을 담당했습니다. Spring Boot로 인증, 기업정보, 고객센터, SSE 알림 API를 구현하고 React 화면을 연동했습니다. 나라장터에서 조회한 면허와 사용자가 직접 등록한 면허는 출처와 상태를 분리해 외부 조회 결과가 바뀌어도 이력이 사라지지 않도록 설계했습니다.

AI 영역에서는 FAQ RAG 챗봇과 첨부문서 자가 자격 진단을 구현했습니다. 챗봇에는 사용자 역할에 따른 검색 범위, 낮은 유사도 차단, 다중 의도 처리, LLM fallback과 개인정보 마스킹을 적용했습니다. 자가 자격 진단은 문서 전체를 LLM에 맡기지 않고 BGE-M3로 관련 근거를 검색한 뒤 LLM은 근거 유형만 분류하고, 최종 충족 여부는 Spring Boot가 기업정보와 비교하도록 역할을 나눴습니다. AI 장애나 미지원 파일이 발생해도 규칙 기반 기본 진단을 유지하도록 구성했습니다.

이 과정에서 5개 저장소에 118개의 비병합 커밋을 기여했고, AI 자동 테스트 242건, Backend 테스트, 사용자·관리자 Frontend 빌드를 통과했습니다. 모델 구현에만 머무르지 않고 API 계약, 데이터 상태, 사용자 화면과 실패 대응까지 연결한 경험이 백엔드·AI 응용 개발자로서의 강점입니다.

## 자기소개서 4. 최근 기술에 대한 견해

생성형 AI는 모든 판단을 대신하는 기능보다, 사람이 확인할 수 있는 근거와 함께 반복 업무를 줄여주는 기능에서 먼저 신뢰를 얻을 수 있다고 생각합니다. 특히 입찰 자격처럼 잘못된 확정이 사용자 의사결정에 영향을 주는 영역에서는 모델의 자연어 처리 능력과 규칙 기반 검증을 분리해야 합니다.

BidMatch에서 자가 자격 진단을 구현할 때 BGE-M3는 관련 문서 근거를 찾고, LLM은 근거 유형을 분류하며, Spring Boot는 기업정보와 비교해 최종 상태를 계산하도록 설계했습니다. 또한 불확실한 조건은 충족으로 단정하지 않고 원문 확인이 필요하다고 안내했습니다. 이를 통해 AI의 활용 범위를 넓히는 것만큼 실패 방식과 책임 경계를 설계하는 일이 중요하다는 것을 배웠습니다.

앞으로도 새로운 모델을 빠르게 적용하는 데 그치지 않고, 평가 데이터와 로그, fallback, 개인정보 보호를 함께 설계해 사용자가 신뢰할 수 있는 AI 기능을 만들고 싶습니다.
